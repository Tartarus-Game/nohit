## 1. Test Philosophy & Core Methodology

The End-to-End (E2E) Testing Track establishes a strict, requirement-driven, opaque-box verification baseline for the entire Sans Fight solving system.

### 1.1 Guiding Principles
1. **Decoupled Opaque-Box Validation**:
   Tests interact strictly via public CLI interfaces and published schemas:
   - Solver output schema: `tools/operator-results/<attack_name>.json`
   - Independent 240Hz Replay Runner: `tools/test_oracle_replay.mjs`
   - Foreground Desktop Browser Acceptance Runner: `tools/verify_and_run_live.mjs`
   - REST endpoints: `GET /api/tas`, `POST /api/oracle-plan`, `POST /api/acceptance`
   Internal implementation choices (e.g. queue memory layout, BitSet operations, Numba dispatch) are opaque to the E2E verification layer.
2. **Authoritative Construct 2 Replay Oracle**:
   Every candidate action sequence generated by the solver must be independently validated against the authentic Construct 2 runtime export (`c2runtime.js` + `data.js` via `c2-sans-fight/engine_oracle.js`) at a strict 240Hz microtick rate (4 microticks = 1 control frame @ 60 FPS).
3. **Strict Invariant Enforcement**:
   - `startHP == 92`
   - `minHP == 92` throughout all ticks
   - `maxKR == 0` throughout all ticks
   - `totalHits == 0`
   - `status == "end_attack"`
   Any damage, KR accumulation, or failure to trigger `EndAttack` represents an immediate, unrecoverable test failure.
4. **Three-Phase End-to-End Verification Pipeline**:
   ```
   [ Phase 1: Python FRS-DP Solver (<1s hot search) ]
                         |
                         v
   [ Phase 2: 240Hz Independent Offline Replay (HP 92 / KR 0 / hits 0) ]
                         |
                         v
   [ Phase 3: Visible Foreground Desktop Chrome (3 Consecutive Rounds EndAttack @ Port 8103) ]
   ```
5. **No Cheating & Zero Facade Guarantee**:
   All tests execute against real physics simulation and real browser execution. Headless mode in live acceptance is strictly prohibited. State perturbation space must preserve all 9 perturbation members (45-field product dynamics).

## 2. Four-Tier Quality Assurance Methodology

The testing suite enforces a rigorous 4-Tier QA ladder combined with an exhaustive battle-tier taxonomy:

```
+========================================================================================+
|                              E2E TESTING TRACK MATRIX                                  |
+========================================================================================+
| DIMENSION A: QUALITY ASSURANCE LADDER      | DIMENSION B: CANONICAL BATTLE TIERS       |
+-------------------------------------------+--------------------------------------------+
| Tier 1: Feature Coverage (>=5 / feature)  | Battle Tier 1: Orthogonal Bone Gaps/Slides |
| Tier 2: Boundary & Corner Cases (>=5 / f) | Battle Tier 2: Platforms & Bone Stabs      |
| Tier 3: Cross-Feature Interactions (Pair) | Battle Tier 3: Gaster Blasters & Multi     |
| Tier 4: Real Scenarios & Full Pipelines   | Battle Tier 4: Sans Final & Real HELL      |
+========================================================================================+
```

### 2.1 Tier 1: Feature Coverage Track (Minimum 5 Tests Per Feature)
Every system feature ($F1$ through $F14$ from `PROJECT.md`) must possess at least 5 targeted verification cases exercising the primary specification under nominal conditions:
- **F1 (Authentic Substrate & Attack Alignment)**: SHA-256 asset verification, 23 CSV schema validation, C2 runtime integrity, variable table mapping, layout initialization.
- **F2 (Universal Wave Compiler & Geometry Parser)**: Linear bone extraction, platform convection schedule, stab warning windows, Gaster blaster OBB parameters, dynamic arena resizing timeline.
- **F3 (Dual-Plane C-Space Hazard Bitmask Baker)**: White plane unconditional lethality, Blue plane velocity gating, 8x8 Minkowski sum dilation, bitmask slice indexing, temporal dimension shape consistency.
- **F4 (Universal 240Hz Dynamics Stepper)**: Blue heart gravity ladder transitions, Red heart 2D kinematic stepping, platform adhesion snap ($y = y_{top} - 8.05$), upward platform jumpthrough, SansSlam boundary collision collapse.
- **F5 (Complete Topological DAG-DP Engine)**: Queue double-buffering, 45-field float64 state stepping, 1D flat boolean Bellman deduplication, O(T) parent pointer trace reconstruction, sub-pixel escape path discovery.
- **F6 (Decoupled Timing & Performance Profiling)**: Compilation time measurement, C-space baking profiling, hot search wall-clock isolation (<1s target), trace reconstruction timing, memory peak tracking (<100MB).
- **F7 (Parameterized 240Hz Independent Replay Engine)**: CLI parameter parsing, dynamic CSV loading, dynamic microtick assertion, 0-damage invariance check, bisection clearance measurement.
- **F8 (Parameterized Foreground Live Acceptance Runner)**: WebSocket connection to Chrome, window foreground positioning (1280x800), continuous 3-round tracking, HUD badge detection (`#tas-status-badge`), telemetry persistence.
- **F9–F14 (Battle Tiers 1–4 & Real HELL Verification)**: Individual wave solution discovery and replay validation.

### 2.2 Tier 2: Boundary & Corner Cases Track (Minimum 5 Tests Per Feature)
Exercises edge coordinates, kinematic saturations, temporal endpoints, and extreme inputs:
1. **Spatial Extremes**: Left wall clamp ($x=0$), Right wall clamp ($x=W-w$), Floor clamp ($y=0$), Ceiling clamp ($y=H-h$), Dynamic arena contraction crushing prevention.
2. **Kinematic Extremes**: Jump hold held to $\tau_{max} = 15$, Instant jump release ($\tau=1$), Maximum falling velocity saturation ($v_y = -750$ px/s), Zero-velocity resting invariance, Sub-tick microstep velocity transition.
3. **Temporal Extremes**: Minimal attack horizon ($T=1$), Frame 0 immediate hazard spawn, Frame 0 SansSlam, EndAttack on final microtick, Inter-frame clock desynchronization tolerance.
4. **Hazard & Safety Margins**: Raw hazard clearance deadband ($\ge 3.5$ px), Minkowski mask safety margin ($\ge 2.0$ px), Platform edge margin ($\ge 6.0$ px), Maximum platform center deviation, Blue bone zero-velocity deadband.
5. **Resource & Failure Extremes**: Frontier memory cap saturation, Solver budget exhaustion handling, Synthetic unavoidable deadlock 100% early detection ($t^* \le T$), Malformed plan JSON recovery, Missing asset handling.

### 2.3 Tier 3: Cross-Feature Interactions Track (Pairwise Combinations)
Tests synchronization and state resolution across coupled mechanics:
1. **Interaction 1: Jump Ascent + Moving Platform Convection**: Horizontal drift during grounded contact vs detached inertia during ascent.
2. **Interaction 2: SansSlam + Ground BoneStab**: Slam collapses soul to floor followed immediately by rising spikes; verifies reaction window and state reset.
3. **Interaction 3: Blue Bone Movement Gate + Platform Convection**: Soul standing stationary relative to platform surface while platform translates; verifies blue bone collision filter.
4. **Interaction 4: Gaster Blaster Beam + Orthogonal Bone Grid**: Composite hazard overlap in shared space; verifies dual-plane bitmask resolution.
5. **Interaction 5: Inelastic Landing + Immediate Jump**: Soul touches platform/floor on tick $t$, resetting $\kappa=1, \tau=0$; jump key re-engages on tick $t+1$.
6. **Interaction 6: Moving Platform + Arena Wall Clamping**: Platform transports soul into arena perimeter wall; soul clamps safely without clipping or infinite acceleration.
7. **Interaction 7: One-Way Jumpthrough + Rising Floor Spikes**: Jumping up through a platform from below to escape rising ground stabs.
8. **Interaction 8: Variable Arena Resizing + SansSlam**: Arena boundary animates while slam forces soul against moving wall.

### 2.4 Tier 4: Canonical Attack Battle Scenarios & Real-World Integration
Executes the full 3-phase verification pipeline across all 23 canonical rounds and Real HELL.

## 4. Verification Interfaces & Invocation Contracts

### 4.1 Phase 1: Solver Plan & Result Contract
Every solved route is stored at `tools/operator-results/<attack_name>.json` conforming to:
```json
{
  "attack": "<attack_name>",
  "status": "candidate_found",
  "frames": 438,
  "actions": [[0, 1], [1, 0], ...],
  "expansions": 4820,
  "timing_ms": {
    "csv_compile": 3.2,
    "cspace_bake": 8.5,
    "hot_search": 142.0,
    "reconstruction": 0.04,
    "wall_clock": 153.74
  },
  "fidelity": {
    "perturbation_members": 9,
    "product_fields": 45,
    "lossy_approximation": false
  }
}
```

### 4.2 Phase 2: Independent 240Hz Replay Runner Contract
- **Script**: `tools/test_oracle_replay.mjs`
- **CLI Syntax**:
  ```powershell
  node tools/test_oracle_replay.mjs --attack <attack_name> --plan <plan_json_path> [--seed <seed>] [--max-ticks <N>] [--timeout <ms>]
  ```
- **CLI Options**:
  - `--attack <name>`: Target attack script name (e.g. `sans_bonegap1` or `sans_bonegap1.csv`).
  - `--plan <path>`: Path to solver candidate plan JSON.
  - `--seed <seed>`: Pseudo-random seed (default: `42`).
  - `--max-ticks <N>`: Maximum microtick execution bound (default: `30000`).
  - `--timeout <ms>`: WebSocket / evaluate timeout in milliseconds (default: `60000`).
- **Pass Semantics**:
  1. Process exit code is `0`.
  2. Replay status is strictly `"end_attack"`.
  3. Action sequence executed to completion (`frames == actions.length`).
  4. Total microticks equals `actions.length * 4`.
  5. `startHP == 92`, `endHP == 92`, `endKR == 0`, `totalHits == 0`.
  6. Hazard clearance deadbands:
     - `min_clearance_raw_c2 >= 3.5` px (or geometry clearance $\ge 3.5$ px).
     - Minkowski mask clearance $\ge 2.0$ px.
     - If platforms exist: `min_platform_edge_margin >= 6.0` px.
  7. Registers plan to dashboard server (`POST /api/oracle-plan`) and exports result to `tools/operator-results/<attack_name>-oracle-result.json`.

### 4.3 Phase 3: Foreground Visible Live Acceptance Contract
- **Script**: `tools/verify_and_run_live.mjs`
- **CLI Syntax**:
  ```powershell
  node tools/verify_and_run_live.mjs --attack <attack_name> --plan <plan_json_path> [--continuous <N>] [--seed <seed>] [--timeout <ms>]
  ```
- **CLI Options**:
  - `--attack <name>`: Target attack script name.
  - `--plan <path>`: Path to candidate plan JSON.
  - `--continuous <N>`: Number of consecutive rounds required (default: `3`).
  - `--seed <seed>`: Random seed (default: `42`).
  - `--timeout <ms>`: Total timeout for multi-round completion (default: `180000`).
- **Pass Semantics**:
  1. Desktop Chrome window positioned in foreground (bounds `1280x800`). **No headless mode**.
  2. Protect running services: Port 8102 (PID 34176) and Port 8103 (PID 48540) must **never** be killed.
  3. Game runs at normal speed on `http://127.0.0.1:8103/game/index.html?mode=single&attack=<name>&seed=42&acceptance=1&continuous=1&candidate=<id>`.
  4. Exact $N$ consecutive rounds trigger `EndAttack` without interruption.
  5. Across all microticks in all $N$ rounds: `HP == 92`, `KR == 0`, `hits == 0`.
  6. HUD status badge element `#tas-status-badge` displays `"实时三回合无伤已通过"`.
  7. High-resolution screenshot captured and persisted.
  8. Telemetry trace persisted to `tools/real-game/`.
  9. Process exit code is `0`.

## 5. Test Suite Hierarchy & Runner CLI

### 5.1 Automated Runner Test Suite (`tests/e2e/test_replay_runner.py`)
Validates that the test runners themselves behave correctly across all inputs and error paths:
- CLI argument parsing (`--attack`, `--plan`, `--seed`, `--continuous`, `--timeout`, positional fallbacks).
- Missing argument, missing plan file, and non-existent attack validation (clean non-zero exit).
- Malformed plan JSON syntax error handling.
- Dynamic frame and tick assertion logic (no hardcoded constants).
- Conditional platform geometry detection (gracefully handles waves without platforms).
- Invariant violation detection (simulated damage triggers clean exit code 1).
- Backward compatibility with legacy invocations.

### 5.2 Unified Test Suite Runner Commands

## 6. Acceptance Criteria & Failure Triage

| Condition | Observation | Root Cause | Remediation |
|---|---|---|---|
| Replay Frame Mismatch | `frames != actions.length` | Solver route truncated or C2 loop mismatch | Re-solve wave with exact duration bound |
| Damage / KR Accumulation | `end_hp < 92` or `end_kr > 0` | Microstep collision probe detected overlap | Increase clearance cost in FRS-DP Bellman folding |
| Replay Timeout | Oracle not ready within 60s | Construct 2 asset load failure or page hang | Verify port 8103 server status |
| Platform Deadband Violation | `margin < 6.0 px` | Platform edge clearance violated | Constrain platform landing envelope |
| Live Acceptance Round Loss | Round 2 or 3 takes damage | Input timing jitter or non-deterministic RNG | Lock RNG seed to `window.__TAS_SEED` |

This document serves as the authoritative specification for all testing infrastructure across the project.
