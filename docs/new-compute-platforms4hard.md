# Platforms4Hard 新计算核实施记录

> 2026-10-05 晚间续作：现已修正 FRS-DP 的精确折叠与搜索限制语义，新候选通过内置浏览器固定步长回放及正常时钟连续三轮无伤。当前候选使用精确折叠、beam 1000，热搜索约 2.4 秒；不剪枝全展开仍触发资源上限。最新证据和复现见 [FRS 内置浏览器验收记录](frs-iab-acceptance-20261005.md)。下文保留早期实现与实验历史，早期“默认 DFS”和“最新尚未通过”不代表当前入口。

## 实际实现

主线现在有可以执行的纯计算切片：`compact_wave.py` 从经审核的 CSV 展开外生骨头和平台，`compact_lattice.py` 用 Numba 执行微步、碰撞和状态图遍历，`compact_solver.py` 返回路线、模型范围、资源状态及分阶段计时。求解时不读取已有路线，不运行 C2，不保存或恢复原版快照。

该切片只支持当前 SHA256 为 `2c23db06eccc8f7eda2341abafb4ebfe9162f3e7ed5bfe026f73f4ea19a42cd2` 的完整 Platforms4Hard CSV、4×4 伤害盒及 438 个60Hz控制帧。`compute=compact` 请求其他回合、局部时域或命中盒尺寸返回 `unsupported_mechanism`，不会切换原版搜索。

## 状态及规则依赖

本回合模式和重力方向固定；脚本不读取玩家位置、没有路径相关随机调用。环境可以共享。影响后继的玩家字段为 `x,y,dx,dy,previous_up`：前一微步速度决定本微步位移，跳跃依赖 Up 边沿；平台支撑由同层坐标及平台几何重新判断。重力是每微步清零后按速度分段计算的局部量，不能误当持久状态。

五个字段保留 float64 位模式。精确比较包含全部字段；哈希碰撞后比较完整状态及时间层。没有坐标取整、速度分箱或 beam 裁剪。整数版本曾在 `dy≈15` 的分段端点与原版发生分歧，已移除。

正常时钟反例还揭示了首回合与后续回合的初态不同：菜单进入首回合带有下落动量，后续回合可能从地板静止速度开始。新版本使用三个初态的乘积状态（校准初速58.5、0.75、0），对每个候选操作同时转移并检查三个成员；完整键保存全部15个字段。任一成员受击就拒绝该操作。这是三个声明初态的共同路线，不代表连续初速区间或任意实时钟的形式保证。

接触使用16×16角色精灵：先水平移动，再垂直移动及 rollback，再跳跃/释放、重力、平台贴合和输入速度赋值。平台落地偏移8.05、反射后极小的垂直速度都保留。平台表仅覆盖已审核的1752微步时域，不冒充通用反射公式。

## 时间、几何和差分

`tests/fixtures/platforms4hard-clock.json` 只含原版校准时钟及真实初态，不含路线。微步积分使用其中的 dt；它不是任意实时钟模型。完整差分夹具另存，只有测试读取其中动作。

四组微步测试覆盖原版参考路线、走出平台、长按及短按跳跃；逐项比较 x/y/dx/dy，容差1e-8。CSV编译的危险物几何在相关区域逐微步与原版捕获双向对照，同样使用1e-8容差。**这是容差校准，不能称为与 C2 的位级等价证明。**

原版 BoneV 的创建坐标会截断为整数：向下重复第六个及之后的骨头 X 可为362而非363。编译器保留了此细节。空间表为 bbox 膨胀后的保守整数位掩码，分数位置查询四个相邻锚点。表约15.7MB；它可能排除贴边解，耗尽不能证明原版无解。

## 搜索和资源

全层广度展开保留作参照；10万状态限额在第18帧触发 `resource_limit`。默认采用深度优先的布尔可达性遍历，完整枚举六种操作，按平台距离和短期预测排序；预测只改变顺序，不删操作。只在所有后继失败后把完整状态记为失败；没有代价最优性声明。

默认配置水平余量1px、垂直余量2px，12帧预测排序，最多1000万展开、200万失败状态。达到上限明确返回资源失败；当前没有续算/落盘实现，不宣称无限容量。更窄余量的实验曾找到更快路线，也曾在正常时钟下受击，不能把它当默认稳定方案。

## 冷处理及算子

Python位掩码算子和原生位掩码算子输出逐位一致；同一几何上的三次测量约332ms与6–7ms。比较只复用几何，未复用路线；数据见 `tools/operator-results/compact-collision-ab.json`。

低余量实验的完整搜索约851ms，但实时稳定性不足。默认较大余量搜索约4.2秒，已有磁盘机器码缓存的新进程返回路线约4.9秒，其中一次轨迹重建触发约577ms编译。这些数字不包含Python导入和游戏加载，不得标成整个冷启动耗时。当前没有达到全流程毫秒级或全流程1秒。

`kernel_load` 分别记录碰撞、搜索及重建的内存命中、磁盘机器码命中和编译。每次 `solve_platforms4hard` 都重新展开CSV、重建掩码和求解；不读取环境缓存或路线缓存。

## 页面入口及验收

`index.html?...&compute=compact` 会等待初次路线生成再创建原版运行时，避免解算期间回合已经开始。自动检测同一回合时保留已有路线，不重复冷算。新核路线按原计算输入执行；原有横向偏差补偿不再改写它的按键。偏差仍记录在HUD。原版 HP、KR、位置、碰撞及正常时钟不做修改。

搜索优先尝试第一帧中性输入，使测得的初始向下动量先稳定在平台上；其他初始操作仍可回溯，不被裁剪。结束微步保留危险几何作为保守相位保护，没有把未来仍可能危险的微步清空。

已取得新核路线的固定步长无伤回放，并取得早期低余量候选的正常速度三回合通过记录；后续测试也产生了实时受击反例，最新严格按键版本尚未通过。固定步长成功或一次三回合通过都不能推广为任意时钟下必定无伤。验收成功、失败及首个受击摘要见 `tools/real-game/platforms4hard-compact-acceptance-summary.json`。此前验收通过的默认参照路线已恢复，新核仅通过显式实验入口运行。

相关测试覆盖微步差分、几何差分、完整状态比较、碰撞锚点、资源失败、未知机制门禁及完整新核API。原有仪表盘测试中的4处断言仍期待旧英文标题/把搜索结果标成原版死局；这轮没有修改这些接口或放宽新核检查。

下一缺口是对实时钟误差和未执行按键边沿的鲁棒求解/控制，以及其他回合的能力实现。当前只有一个经校准的计算切片，不能称为所有原版回合的新核已经完成。
