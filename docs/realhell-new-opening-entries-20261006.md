# 从初态重新展开 Real HELL 的更早入口

目标是解除旧诊断 tick500 单一状态的条件限制。旧500起点向后完整耗尽，只能证明该起点与其声明控制格点下无解，不能证明原战斗无解。

采用原始 CSV、seed42、已有原生初始相位与240Hz时钟参数、已修正 Fire hotspot；没有原生分支回放。所有运动与碰撞执行现有精确算子，不修改源攻击。

## 早期切点

源事件：tick0 teleport；tick120 四向骨刺；tick216 首次 SansSlam；随后300、384、468再次slam；tick610转红并创建第一组blaster。tick0之后直到610不存在位置重置。Slam重置速度/方向，不能合并不同位置。

完整4tick、16箭头mask、内部旧输入latch商，从初态到212仅121种xy；此处位于首slam前，是更合适的完整入口切点。独立完整终态及所有父链保存 `scratch/earlier-blue-0-212-hold4/`。继续完整4tick展开，150k层预算到336仍保留135,050个等价类，64,702种xy；下一层超预算，结论unknown，未丢弃前沿。保存 `scratch/earlier-blue-0-500-hold4/`。

## 新的可行500入口

以每20tick持键、全部16mask的受限控制域完整展开0→500，得到5,376个完整终态、852种xy，求解0.44s。20是4的倍数，全部见证可以展开为合法4tick控制词。终态x范围 `[260.4447916656,264.6703124990]`，与旧诊断500的 `267.7244791657` 不同；所有5,376个状态都不受旧500单起点耗尽结论覆盖。

独立逐tick重放全部5,376个见证，共2,688,000物理tick，碰撞0，全部11维终态逐bit匹配。产物 `scratch/earlier-blue-0-500-hold20/` 中保存完整出口、父链、20tick与4tick见证及 verification.json。这个受限域只用于尽快得到确切可行入口，不代表替代完整4tick/1tick域；此前完整4tick前沿仍保留。

## 多入口关系组合

对全部5,376个500出口用4tick全16控制完整传播到612，得到1,625,472个full11终态。中间层使用已证明latch商，终态保留全部mask。先1m预算于608停止，随后从已保存608前沿补最后一层，在2.5m预算完成；合计执行107.46s。目录 `scratch/earlier-blue-500-612-stream/` 保留每层父索引和mask，origin索引对应上述5,376个原始500出口。

612起固定红心且下一步不读旧mask，可按已有精确商转resident轴联合关系：930,384类。完整后继计数：616为2,750,895；620为8,167,698；624为13,435,401。628超过15m层预算，**保存624完整前沿，结论unknown**，不是任一新入口死亡。产物 `scratch/earlier-red-612-propagation/`。

624联合集合占轴笛卡尔积 `13,435,401 / 13,597,920 ≈ 98.8%`。当前每联合节点保存id/parent/mask约17字节；密集联合bitset加事后逆转移查见证，有望无损降低存储和枚举开销。该建议尚未在本实验实施，不能计作已获得优化。

跨三段完整origin闭环已经核验4条见证：resident624索引→转换612的源索引→stream500 origin→原初态0控制词；每tick无伤且最终11维逐bit一致。验证结果保存 `origin-verification.json`。这只验证所抽见证的组装，完整集合关系的正确性仍依据各层精确转移与既有算子测试。尚未跨过Real HELL首个难点，更没有完成原版全程无伤。
