# 人类友好搜索与路线难度报告

新增 `objective='human_friendly'`。原有 `fewest_operations` 只优化方向键组合的变化次数；新模式同时考虑搜索安全余量、操作变化和自然指法，并生成可核对的难点报告。

## 使用

Dashboard → 高级设置 → 路线偏好 → **人类友好：优先容错，再减少换键**。会自动勾选难度分析，也可以关闭。报告显示在路线执行难度面板；选择重点位置可跳到对应预览 tick，跳转远处需要完整几何预览。

```sh
python -m tools.solve_csv attack.csv --entry entry.json --out result.json \
  --objective human_friendly --seconds 60 --width 512 --workers 4
```

API 接受 `objective: "human_friendly"` 和 `analyze_difficulty: true/false`。省略后者时，人类友好模式自动分析，其他模式默认不分析。命令行可用 `--no-analyze-difficulty` 跳过报告，或单独用 `--analyze-difficulty` 分析其他模式的结果。原游戏标签页同样传递这两个选项。

## 搜索目标与操作

每个窗口按 **12、6、3、0px** 四档尝试额外安全余量，先尝试较宽的一档。每档先用快速策略找安全候选，再用剩余预算减少操作；在该档已经找到的候选中选择方向换键代价更低者。默认每次方向组合变化计 1000 分代价，奖励为负代价；长按不增加换键次数。

余量通过扩大搜索碰撞框实现，原有 4×4 判定盒额外向每侧扩张指定像素。白骨、移动状态下的蓝骨和旋转光炮都使用原有碰撞规则；蓝骨的静止免伤条件保留。较大碰撞框不会使用只适用于原尺寸的空格子索引来放行。实际世界的窗口校验也检查所选余量，最终完整源程序验证仍使用原始物理与判定盒。

人类友好模式只生成静止、单方向或两方向对角组合，禁止左右同按、上下同按。该约束同时用于普通前沿、恢复、宏动作和快速策略；含相反方向的固定前缀会被明确拒绝。其他模式继续保留原来的输入集合。

Confirm 只在交互对话可完成时发送。对于显式时钟，保留已有确认时钟槽，并检查本 tick 最后一个字符是否将显示完成，避免删除无效按键时意外改变已有文本回调相位。没有对话时不生成连续连按。

这属于有限窗口、多档目标的启发式搜索。没有证明全局最大余量、最少操作或人类最优路线；没有额外试探的余量值不构成最优性证据。更严格的目标和自然指法限制可能降低预算内的搜索成功率。

## 难度报告

输出位于 `result.difficulty`，包括：

- `minimum_clearance_px`：原始源程序重放中，4×4 判定盒距离激活危险的最小额外单侧扩张量，使用 L∞ 度量。它不是走廊总宽，也不是整个运动过程的扰动保证。相邻 tick 之间没有额外连续碰撞证明。
- `hard_points`：重点位置的 tick、实际累计秒数、余量、危险类别及 CSV 执行游标。游标不一定是危险实体的创建行。
- `timing_events`：默认最多选 24 个操作事件，兼顾狭窄位置与时间分布。将换键边界或整个 Confirm 脉冲提前／延后 1–4 tick，重新执行该分支自己的源程序、GetHeartPos 和物理。
- 时序探测保持其他控制不变，默认只检查随后 0.5 秒，最多 240 tick；不是临场补救搜索，也不验证扰动后的完整后缀。正负一 tick 都产生实际碰撞才标记 `frame_exact_locally`。未测试、邻近操作阻挡或资源不足不会冒充“必死”。
- `blue_motion_lock_windows`：静止时和蓝骨重叠、移动会激活碰撞的区间，与空间余量分开列出。
- `operations`：方向组合变化、单键按下／释放边沿、Confirm 按下及有效对话确认次数、峰值操作密度、最短方向保持时间、最大同时按键数与相反方向帧数。

评分为 **0–100 的启发式 v1**，综合狭窄移动、局部一 tick 敏感度和输入事件密度。未用真人成功率校准。单纯在狭窄位置静止不会自动被当作需要精密移动。极小的浮点余量还可能来自脚本、平台或墙体固定坐标，不能直接换算成人手定位精度或成功概率。

`human_feasibility` 给出“抽测窗口未见明显障碍／可能极难手动执行／仍不确定”及原因，不编造成功概率。搜索失败不评分，不判定人类无解。一条难执行的固定路线，不证明没有更好的路线。用户已报告 Real HELL 可真人无伤；下面评价的是求解器路线，并不否定这一事实。
