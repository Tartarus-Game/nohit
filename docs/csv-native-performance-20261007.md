# CSV 原版模型与完整请求性能验证

本报告的计时均在相同的实际原版入场请求上比较，包含完整求解、独立模型重放和
可视化输出。失败重试计入每轮总成本。固定 `OMP_WAIT_POLICY=PASSIVE`，不并发
运行其他求解或基准。单次完整请求测量保留原始结果；局部批次另做 31 轮交错计时。

## 已通过的原版执行

8144 的 24 轮 Normal 已原版无伤到 Win2，独立验收 `passed=true`，连续 68,243
tick 保持 HP92/KR0，615,527 个非终态玩家分量与模型精确相同。记录、截图和
125 份已验收源码快照见 [Normal 报告](normal-csv-native-20261007.md)。

该次运行在增加下述“预分配去重表”和“启动准备”之前；当时 22/24 轮累计计算
耗时低于攻击时长。此后的严格等价对照不能冒充新版本的原版执行记录。

## 保持全部输出顺序的选择优化

`selection_buckets.unique_bucket_indices` 先哈希找首代表，再按原 V40 字节顺序
排列唯一桶。完整等值比较处理哈希碰撞；随机数调用、代表顺序、补充选择和父链
保持不变。43 个真实候选批次下标与完整 RNG 状态相同；其中 40 个超过宽度限制
的批次，31 轮计时汇总加速 2.683 倍。正式及近邻测试 114 passed。

真实 Final 请求的完整单变量对照：

| 请求 | 原 NumPy 选择 | 新选择 |
| --- | ---: | ---: |
| width 300，unknown | 8.8595 s | 7.6614 s |
| width 1000，候选 | 45.1933 s | 36.6686 s |
| 含失败重试合计 | 54.0528 s | 44.3299 s |

攻击为 52.5708 s。完整语义 JSON 与 float64 轨迹哈希相同；见
`scratch/campaign-csv-native-20261007/final-frontier-audit/typed-int-selection-api-comparison.json`。

## 预分配精确去重的哈希表

拆分 43 个原始扩展批次显示：哈希阶段约 66.1%，V88 排序约 28.5%。最终仅把
初始容量从固定 1024 改成至少 1024、足以满足输入行数和原 60% 负载限制的
2 的幂。哈希、完整等价判断、首代表、投影和 V88 排序没有改变。尝试过的基数
排序更慢，未采用。

43 批次各 31 轮的中位数合计从 43.4885 ms 降至 30.5148 ms，减少 29.8%。
42 个非空批次全部更快；空批次只有微秒级噪声。新增及近邻正式门禁 139 passed。

下表为另一组实际入场请求；勿把不同行的请求初态当作同一个性能样本：

| 当前完整请求 | 原固定容量 | 预分配容量 |
| --- | ---: | ---: |
| RandomBlaster2 width 300，unknown | 2.2107 s | 1.8647 s |

RandomBlaster2 攻击为 8.5875 s。该批完整对照全部动作、Confirm、目标、轨迹、
可视化和非计时统计相同。基线只通过显式诊断覆盖恢复 1024 容量，其他源文件
和参数不变；原始结果标有 `diagnostic_dedup_override`，不伪称未修改运行代码。
完整结果与三个 `*-dedup-comparison.json` 均在上述 `final-frontier-audit/` 目录。

## 首轮编译移到服务就绪之前

此前 Intro 首次请求 42.1641 s 中，bounded 内核物化占 37.6308 s；8144 中
11.2080 s 仍含 7.3277 s 的首次物化。原启动器只准备 canonical 路径，未准备
CSV 使用的扩展、去重、选择和 held trace 等签名。

`warm_csv_kernels` 使用全合成两 tick 数组，在监听 HTTP 前准备 CSV 内核。
它不读取 CSV、不建立输入依赖的世界或路线，不缓存候选。测试验证二次准备
不增加签名、线程掩码恢复、不调用 CSV/绑定/求解入口及启动顺序，2 passed。
热性能实验显式记录这部分启动准备，实际 API 计时仍完整包含请求中的所有工作。

## 证据边界

这些优化改善吞吐，不改变有界搜索的完备性。宽度、目标分支或时间预算耗尽仍
只返回 unknown。原版数学建模也不能只比对玩家轨迹：本轮的 ANGLE 符号与
GasterBlaster 类型敏感取整漏洞都曾在玩家状态逐位相同时漏判原版碰撞。
当前证明仅覆盖记录中的来源、种子、初态、时钟和实现版本；全部自制 CSV、
任意初态和最小伤害最优性仍是单独任务。
