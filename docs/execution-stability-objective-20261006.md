# 无伤硬约束与操作偏好（2026-10-06 最新澄清）

## 当前目标

执行端新增 [卡顿补偿与验收记录](lag-compensation-20261006.md)：不假定实机渲染回调准时，固定逻辑步积累并追赶欠账，每次输入边沿都执行。此调度方式独立于奖励权重；不能把补偿模式通过等同于任意变步长执行保证。

用户说明：奖励函数只是加权，鼓励高评分路线优先成为候选，但其他安全路线也应保留。无论是否加权，都应能找到准确无伤路线；加权改变操作习性。

此前把目标扩大成“先证明完整路线的时序鲁棒性全局最优，再允许 TAS 执行”是助手的过度解读，已撤回。这不是当前交付门槛。

## 同一套搜索的契约

- **硬条件**：从完整初态出发，按声明动作与原版对应转移推进；每个碰撞检查点无伤，并实际到达 EndAttack。
- **软条件**：余量、前瞻、靠近中心、减少按键切换的有限权重只决定队列顺序。零权重仍使用相同的物理、碰撞和终止判定。
- **保留范围**：所有唯一安全后继都进入同一张图；低分不是删除理由。只对未来行为等价的状态合并，不使用 Beam 或坐标取整来删安全分支。
- **输出**：可以选择加权搜索先找到的完整无伤候选，不必枚举所有完整路线或先证明评分的全局最优。原版回放与正常速度验收仍独立执行。
- **失败**：只有在完整有限图中穷尽安全状态，才能报告声明模型内不可达。资源不足、模型缺失、原版回放失败均是 solver 的未完成或错误，不能写成原版无解。

设零权重和任意有效权重下的安全可达集合分别为 R0、Rw：在同一个模型与动作集上，不受资源截断时应有 R0=Rw。权重可以改变搜索时间和选出的路线，不能改变合法输入、物理响应和碰撞结果。

## 当前实现

`adaptive_dag.search` 采用单一有限分数排序：时间深度 + 加权首选余量 + 加权前瞻存活时间 - 加权中心距离 - 加权输入切换。碰撞接受条件固定使用原尺寸，完全不读取权重。

默认权重为 `clearance=1, lookahead=1, center=1, switches=0`。设四项均为 0 可关闭所有奖励，保留确定性的深度优先调度。权重必须是 0–1000 的有限数值；API 支持 `weights` JSON 对象，并将实际权重保存在候选的计算来源中。

原先首选余量的词典序硬排序已换成有限加权分数。即使余量不足或风格评分低，只要真实碰撞检查安全，该分支也保留。

## 验证与限制

`tests/unit/test_adaptive_dag.py` 将零权重、普通权重和极端偏好与两帧全部 36 个输入序列对照；覆盖无解模型、窄路、坏偏好诱导回退、内存增长、资源截断，以及不同风格产生不同但都安全的路线。

历史 3px 与 7.375px 净空反例仅说明首个见证未必是全局最大净空路线，**不违反当前无伤可行性加软偏好的目标**。

`timing_robustness.py` 保留为独立可选诊断工具，不是第二个生产求解器，也不是当前路线输出的全局最优门禁。它的扰动枚举资源限制不应阻止已经满足声明无伤条件的候选进入原版验证。

当前模型仍仅验证了固定框、固定红心/向下蓝心和轴对齐骨阵范围；其余原版机制及全部 23 关验收尚未完成。有限预算下，权重不同可能使一项搜索先找到路线、另一项先触及资源限制；这表示搜索尚未完成，不表示安全路线集合因权重改变。
