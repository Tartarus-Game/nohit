## 查明的问题

1. 同 tick 内创建 BoneH/BoneV 后立刻 BlackScreen(1)、BlackScreen(0)，原版 C2 的 family Destroy 只选中已登记对象，新对象会保留下来。旧模型把它们全部清空。原版回放在相对 tick 9,336 出现 HP/KR 伤害，而模型的危险集合为空；玩家数值状态本身仍逐项匹配。此次修复分别应用到单体参考解释器和可恢复解释器，包含暂停／目标读取过程中保存的登记边界。
2. 文件没有 EndAttack，尾部保留 123 个静止蓝骨。等待所有实体消失永远无法完成。现在源解释器记录完整静止蓝骨清单，释放输入期间逐帧检查，再用零速度固定点及无未来回调条件证明无限尾部安全。
3. 脚本明确把红心传送到 `(114514,1919)`。原版场地 clamp 只在与有限场地相交时运行，场外停止的红心可是真实固定点。旧证明强制位于场内，错误地拒绝了这段安全尾部。

附件含 230 条颜色参数为 1 的 BoneH/BoneV 行，没有颜色为 2 的橙骨行。此次完整回放验证了这个附件的蓝骨处理及上述生命周期问题；不据此声称橙骨全部机制已经验证。

## 原版证据范围

未修改的 Construct 2 `c2runtime.js` 和 `data.js` 直接执行完整路线，仅 DOM、音频、渲染被桩替代。60 Hz 使用实际 binary64 时间戳差；入口、完整 dt 序列、目标读取、源身份及逐帧状态全部保存。原版 27,953 次输入通过，HP 始终 92、KR 始终 0，没有碰撞 DamagePlayer 调用，所有实际目标读取与 11 项玩家状态一致。尾部仍有 123 个静止蓝骨，原版 EOF、空 Wait 队列、静止场地、仅被动 UI、全释放输入和场外红心固定点均已独立观察。

最初无界面运行时的完整求解及模型复验耗时 14.304 秒，游戏时间 465.883 秒；原版回放耗时另列。此为完整最终补全版，不能与此前人为削弱并补充终点的 Real HELL 记录混用。使用已编译算子，不含安装时编译；没有复用路线或世界缓存。

声明时钟原点为 `1800000 ms` 的独立新进程复现，再次完成全程原版无伤回放；该次完整求解及模型复验耗时 **10.346 秒**。入口和逐 tick 时钟随证据保存。另一次宽度 1024 的独立模型求解为 11.279 秒，该结果不冒充另一次原版回放。

未预处理的原文件也单独尝试过：原版第 4 行留空的 KR 参数使首帧 KR 记录为非有限值，严格 HP/KR 验收立即拒绝。该尝试不能冒充原文件完整无伤通过。正常导入会按已有策略禁用该行，以上完整成功结论适用于明确记录的执行源。

不同时间戳相位也另行记录：30 Hz 和某些 60 Hz 相位在开头约 0.93–0.97 秒耗尽当前前沿；不能将某次通过推断为所有帧率／时间戳相位均通过。精确复现应使用保存的入口及完整 dt 序列。无界面工具支持 `NOHIT_CLOCK_ORIGIN_MS` 声明可重现的时间戳原点，仍逐 tick 使用原始时间戳差，不能把它当作消除所有相位差异的物理修复。

## 复现

精选证据位于 `artifacts/realhell-final-20261018/`，摘要绑定原文件、执行源、输入、时钟、原版完整记录与源码复验。`before-fix-*`、`raw-source-rejected-*` 和 `alternate-clock-*` 是明确保留的失败记录，不是成功证据。

```sh
python -m zipfile -e artifacts/realhell-final-20261018/inputs.zip build/realhell-final-repro
python -m tools.solve_csv build/realhell-final-repro/source.csv \
  --entry build/realhell-final-repro/entry.json --termination-policy eof_hazards_drained \
  --seconds 30 --width 8192 --workers 4 --memory-mb 1024 --out build/realhell-final-repro/route.json
```

以上会重新求解，不载入保存的路线。原版记录的完整输入单独保存为 `route.json.gz`；`latest-source-verification.json.gz` 仅重新验证这条已原版回放的路线，不能将其耗时冒充重新求解。数值算子的安装／首次编译不在上述已安装性能数字中。
