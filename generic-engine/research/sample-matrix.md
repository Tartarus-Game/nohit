## 对通用接入设计有实际影响的发现

- Zhazha：`objects/battle_soul_blue/Step_0.gml` 保存 `jump_state`、`on_platform`、方向对应跳跃键，调用 `instance_place`／`place_meeting`；`battle_soul/Step_2.gml` 用 Xpoly 做场地结算。仅依靠 GameMaker sprite 碰撞 API 会漏掉场地自定义算子。伤害入口为 `scripts/Player_Hurt/Player_Hurt.gml` 与 `scripts/Player_HurtKr/Player_HurtKr.gml`，必须两处审计。
- UndertaleMakerX：`runtime/scripts/scenes/encounter_battle/projectile/BaseBattleProjectile.cs` 使用 Area 重叠，并随动画帧切换缓存形状；`battle_player_soul/BattlePlayerSoul.cs` 有独立场地检测和移动判断。`examples/Undertale-SansFight/libraries/blue-soul/blue-soul.js` 保存跳速、slam、支撑平台及平台位移。要同时处理 C# 物理状态与 JS 对象／Set；当前通用示例没有完成这一适配。
- meowjade：`Battle/Soul/soul.gd` 的颜色判定支持按键、速度及二者组合；伤害由 `check_bullet`、`hurt`、`heal` 执行。保持源码现有行为，包括看起来奇怪的橙弹条件，不能擅自改成自己理解的原版规则。
- WDUT：`cpp/engine/Battle/Soul/soul.cpp` 在 `_physics_process` 中查询 Area，并使用与 meowjade 不完全相同的组合条件，部分“组合”条件是 OR。物理顺序也需要实际验证。
- Coalition：`scripts/AddBulletCollision/AddBulletCollision.gml` 注册不同碰撞函数，包括颜色函数和任意用户函数；不能统一替换成几何重叠。
- Tartarus：`battle/battle_soul/BattleSoulRed.gd` 仅声明 `class_name BattleSoulRed extends CharacterBody2D`，缺少可直接复用的弹幕／蓝心算子。适合作为界面参考，不能作为完整求解验证样本。

`source-audit.json` 保存项目位置、文件数量、关键词入口、行号和源码文件 SHA-256。它是自动扫描结果，关键字出现不等于已证明有可运行的伤害或碰撞功能。许可证检测同样只做初步登记，不把没有许可证的项目标成 MIT；交付的是新编写的接入原型、定位信息和解包清单，不捆绑这些上游游戏的完整资源。
