# 通用接入层验收

当前实现支持两种低门槛入口：

- 配置接入：原游戏已有伤害/结束信号，仅填写 JSON 路径、信号、攻击方法和观察属性。
- 脚本接入：一份适配器处理菜单/加载、自定义输入和原伤害入口；不要求世界快照。

两者都启动原主场景与自动加载，保留原引擎物理帧、Timer/Tween、碰撞及伤害规则。
旧 Snapshot 接入保留，用于能精确恢复世界的项目。没有强制重写心魂控制器。

## 已执行证据

`acceptance-v2/acceptance.json`：Godot 3.5.3、4.6.1，共 24 项通过，0 项失败：

| 每版各 12 项 | 结果 |
| --- | --- |
| 重复安装保留原工程与适配器 | 通过 |
| 原生候选 + 新进程回放 + 受伤反例 | 通过 |
| 仅 JSON 配置式接入 | 通过 |
| 漏接伤害审计 | 拒绝通过 |
| 没有原攻击结束事件 | unknown |
| 受伤后立即回血 | 仍判 hit |
| 观察包含 Vector2 等非 JSON 值 | 拒绝通过 |
| 新进程观察故意加入进程 ID | 拒绝回放 |
| 反例路线本身安全 | 不发验证证书 |
| 原结束事件后一帧伤害 | 仍判 hit |
| `_input` 只收一次按下，轮询输入持续生效 | 通过 |
| 4 个隔离进程并行的有限输入策略搜索 | 通过 |

最小示例是自行编写的接入 fixture，不能算成上游游戏关卡。
GameMaker 模板没有可用原生运行时，未纳入这些通过项。

`megalo-common/summary.json`：固定原提交

只添加观察伤害子类并委托原 takeDamage，没有在反例里移动玩家位置。

## 已发现并修复的接入问题

Godot headless 输入注入不能只依赖 `Input.parse_input_event`。
当前代码显式设置 Input action 状态，并将边沿事件送进原输入 Viewport。
独立检查 `_input` 和轮询均生效，子 Viewport 可由配置/适配器指定。
历史专用驱动没有这项保障；本轮通用结果使用修复后的公共 SDK重新执行。

验收证书只覆盖指定场景、种子、路线和适配器审计范围。逐帧观察不是完整世界快照。
伤害反例证明该损伤路径能工作，不自动证明开发者没有漏接其他伤害入口。
冷启动、导入和原攻击时长均保留，不承诺任意原游戏毫秒级执行。

复现命令：

```bash
python generic-engine/tools/test_portable.py --godot3 /path/to/godot3 --godot4 /path/to/godot4 --output results/acceptance
```

调试阶段的首次失败已保留在其他目录，最终完整验收以 `acceptance-v2` 为准。

` sdk-package-smoke/summary.json `：将轻量 ZIP 解压到新目录、安装到带空格的游戏路径后，Godot 4 原生候选、独立回放和伤害反例再次通过。分发包入口与路径处理已实测。
