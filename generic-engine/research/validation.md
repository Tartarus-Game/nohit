# 原型验证

官方 Godot 4.3（77dcf97d8）和 4.6.1（14d19694e），Linux headless：

- 红心与蓝心，各有预定弹幕和追踪玩家弹幕，共四组 45 帧路线。
- 跨场地地面障碍要求蓝心起跳，45 帧无伤路线，测试确认包含跳跃输入。
- 完全覆盖场地的障碍返回 unknown。
- 漏存一个会影响状态的变量时，回放返回 replay_failed。
- 每次搜索结束恢复初始状态。
- 625 个旋转矩形／圆形采样点与逐点原生碰撞调用一致。
- CollisionObject2D 多形状接口抓取、disabled 排除、冻结形状后原资源变化不影响快照。
- 正常场景入口也已 headless 启动，输出完整候选并回放；没有图形 UI 截图验收。

详细路线与耗时在 godot-4.3-tests.json、godot-4.6.1-tests.json。毫秒数据只覆盖这个小示例的搜索及同 host 回放，不能外推到真实关卡或冷启动承诺。这些记录属于协议示例。实际上游接入另见下文。

解包：两个真实 PCK 共 373 条记录，所有带有 MD5 的条目校验通过；未执行包中的代码。另有 7 个标准库测试覆盖 PCK v1/v2/v3、校验失败、截断、路径穿越、ZIP 提取及 FORM 目录。

GameMaker 脚本未编译运行。研究输入为固定 Git 提交；UDTale 尚无包文件。

## meowjade 原生接入验收

Godot 4.6.1 官方标准版，提交 `729dfb7ef9ba41f8695724cb31e5cd360d49128d`。

- 直接运行上游 SceneContainer、Battle、Soul、BulletCircle 和原碰撞／伤害入口。
- 白弹红心、白弹蓝心、蓝弹红心、橙弹红心四组孤立圆环组件，各 300 帧。
- 候选与独立进程回放逐帧完全一致；HP 全程 20、KR 全程 0，无伤害／回血调用，无敌关闭且碰撞监测保持开启。
- 白弹静止、蓝弹移动、橙弹静止三个反例正常受伤。
- 候选烘焙使用原节点形状与 Godot Shape2D.collide；不烘焙的回放得到同样状态。
- 完整 default_attack 的四种策略均在 302–509 帧受伤，未通过。
- 6 个验收故障注入测试通过：临时 KR、回血掩盖伤害、无敌、未完成波次、输入／位置微小偏差均被拒绝。

见 `native-meow-delivery/suite.json` 与 `native-meow-report.md`。实测首次导入约 6.44 秒，全套含并行搜索、四次回放、反例和完整攻击尝试约 22.37 秒；不能把小原型的毫秒数字外推为完整游戏冷启动保证。退出日志仍有上游 ObjectDB／资源引用警告，未过滤或作为长期零泄漏证明；没有脚本解析／执行错误。
